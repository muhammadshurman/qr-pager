QRPAGER-15 — THE FRESH-CLONE PROOF FOR THE FRONTEND WORKSPACE
=============================================================

§6 / CLAUDE.md: "Gates run from a FRESH CLONE, not just a fresh database — a pass that
depends on something only present on the builder's machine is not a pass."
QRPAGER-15 §7: "Fresh CLONE: the workspace builds, lints and tests with nothing that only
exists on the builder's machine."

Produced by tools/gate/bin/fresh-clone-proof, the sibling of
apps/api/bin/fresh-clone-proof. `git clone file://…` goes through the transport rather
than hardlinking the object store, so the clone shares no object with the working tree,
and the script REFUSES to continue if node_modules/ or .next/ arrived with it.

WHAT IT PROVES: the REPOSITORY is sufficient. Every file the gate reads is tracked, and
the pinned versions in package.json, .nvmrc and pnpm-lock.yaml reconstruct the toolchain.

WHAT IT DOES NOT PROVE: that the machine is bare. The pnpm store and Playwright's browser
cache are the host's, and both are CACHES rather than sources — a cold one costs time, not
correctness. The script reports which it got, and it got warm ones.
