# This is the acceptance evidence R-083 names and the overnight run deliberately did NOT
# write, because the design it had to be built around was Muhammad's to choose:
#
#   "a two-process proof (outbox:work --once twice over, lease_seconds=1, batch_size=8,
#    an edge that sleeps ~1 s per send) asserting EACH ENDPOINT RECEIVED EXACTLY ONE
#    REQUEST — which should be RED on the current head"
#
# ⚠ ONE PARAMETER IS DELIBERATELY DIFFERENT, and the reason is a correction to the gate
# rather than a convenience. THE SEND IS 250 ms, NOT ~1 s. A ~1 s send against a 1 s
# lease is a configuration in which NO per-row re-lease can hold: the fix bounds the
# duplicate window by ONE ROW'S processing, so the lease must EXCEED one row's
# processing. At 1 s against a 1 s lease the worker loses the row WHILE sending it and
# no statement placed before the send can see that coming. lease_seconds=1 and
# batch_size=8 are used verbatim. Written down rather than quietly adjusted: as
# specified, the gate's parameters describe a system that cannot satisfy the gate.
#
