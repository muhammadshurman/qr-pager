⚠ WHAT THE POSITIVE CONTROL CAUGHT, because it is the point of having one.
The first version of Task 7's privilege block asked has_table_privilege() for
every privilege. That function answers `f` for a COLUMN-level grant -- it asks
only about the table-level one -- so:

    has_table_privilege     ('qrpager_app','media_assets','INSERT')  ->  f
    has_any_column_privilege('qrpager_app','media_assets','INSERT')  ->  t

Every one of the worker's absence checks would therefore have answered `f` for
a worker holding a column-level grant on every column: the control passing
while the thing it forbids was true. The positive control failed loudly
("qrpager_app does NOT hold INSERT on media_assets -- the absence checks above
are vacuous") and the block now uses has_any_column_privilege for the column
privileges and keeps has_table_privilege for DELETE, which has no column form.

That is the same shape the script's own DELETE comment already recorded for
passkeys, arriving from the other direction.
