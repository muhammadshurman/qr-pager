R-191 — THE MECHANISM, WHICH THE ROW HAD WRONG

  The row read "no connect_timeout is configured anywhere ... so the message is
  libpq reporting an OS-level connect() that did not complete". The premise is
  true of this repository and the conclusion does not follow: pdo_pgsql appends
  connect_timeout ITSELF, from PDO::ATTR_TIMEOUT, defaulting to 30, whenever any
  driver option is passed — and Illuminate's Connector always passes five.

    ATTR_TIMEOUT = 3     failed in  3.01s   SQLSTATE[08006] ... timeout expired
    Laravel's defaults   failed in 32.75s   SQLSTATE[08006] ... timeout expired

  So a 30-second deadline nobody chose had been in force since Task 1, against a
  host whose stall this repository had already measured twice without the two
  numbers being put together: AppPoolSaturator's 32.430s (read correctly there as
  SYN retransmission) and R-191's own 35,648ms with 0 OF 300 CONNECTS FAILING.
  The connects were succeeding; the undocumented deadline expired first.

  Bounded locally and NOTHING in production changes: the deadline is explicit at
  30 in config/database.php (the value always in force), the suite gets 45, and
  RetryingPostgresConnector absorbs one stall per connect — bound from
  Tests\TestCase through db.connector.pgsql, so no production file is touched.
  THREE GENUINE STALLS WERE ABSORBED ACROSS TEN GATE RUNS ON 2026-11-07, EVERY
  RUN GOING GREEN. Each would have been a red run before this task. The retry,
  not the raised deadline, is the load-bearing half: one of those stalls expired
  the 45s too.

  NOT CLOSED. The host fault is untouched and the production deadline question
  stays with Task 13. R-241's original red stays UNATTRIBUTED.
