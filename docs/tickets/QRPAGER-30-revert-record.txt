⚠ FIVE FAILURES, AND FOUR OF THEM ARE `QueryException` FROM `makeTenant` — WHICH PROVES
THE TRAP RATHER THAN THE ASSERTION. `QRPAGER-30 §5` says *"the default belongs in the
DATABASE; a code default would make a row inserted by anything other than the app's own
path carry nothing, and NOT NULL would then fail at a distance from the cause."* With the
default gone, `NOT NULL` fires on every tenant insert that does not name the column —
which is every one of them, including the test harness's own. That is the failure "at a
distance from the cause" happening, measured, in the four cases that never mention a
default.

and the suite is green again:
